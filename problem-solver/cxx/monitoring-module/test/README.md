# Ручная проверка группы A в sc-web

Найди ситуацию по системному идентификатору из таблицы. Чтобы увидеть ответ графом, включи экспертный режим и выбери представление SCg. Нажми правой кнопкой на узел ситуации и выбери команду. Через верхнее меню «Анализ оборудования» ту же команду можно запустить, предварительно закрепив ситуацию кнопкой-булавкой. Каждый запуск создаёт отдельную запись в истории.

| Агент | Команда | Что проверить на графе |
|---|---|---|
| A1 | Проверить достоверность показаний | Датчик, статус и каждая установленная причина недостоверности |
| A2 | Сравнить показания с уставками | Направление нарушения, узел конкретной уставки датчика и наблюдаемая длительность в минутах |
| A3 | Спрогнозировать выход за уставку | Направление, время в минутах и скорость в единицах датчика за минуту |
| A4 | Оценить износ оборудования | Модуль, степень деградации и выявленные признаки |
| A5 | Определить контекст ISA-88 | Состояние аппарата, процедура, фаза, модули и основание штатности показаний |
| A6 | Классифицировать ситуацию объекта | Для отклонения — экземпляр класса, принадлежность классу нештатных ситуаций, место, критичность и вероятная причина |

«Оценить состояние объекта» собирает доступные оценки A1–A5 в один граф. «Классифицировать ситуацию объекта» сначала получает свежие оценки, затем передаёт их A6. Обе команды принимают один исходный узел.

|---|---|---|

| `mon_case_idle` | A5, A6 | Тот же датчик и такие же значения. Основание штатности — Idle. Штатная ситуация |

| `mon_case_normal` | A2, A6 | Значение 80 на границе входит в допустимый диапазон. Штатная ситуация |
| `mon_case_temperature` | A2, A6 | Наблюдается перегрев длительностью 5 минут. Температура вне режима |
| `mon_case_brief` | A2, A6 | A2 показывает превышение в течение 2 минут. Для аварийной классификации требуется 5 минут. Штатная ситуация |
| `mon_case_forecast` | A3 | Рост на 0,5 °C/мин, верхняя уставка через 12 минут |
| `mon_case_cooling` | A3 | Снижение на 0,5 °C/мин, нижняя уставка через 10 минут |

| `mon_case_valve` | A6 | Таймаут команды и отсутствие подтверждения. Клапан не достиг положения |

| `mon_case_pump` | A4, A5, A6 | Значительная деградация насоса по току, времени срабатывания, циклам и наработке. Класс «перегрузка или износ насоса» |

| `mon_case_stuck` | A1, A6 | Недостоверный датчик. Причина — залипание |
| `mon_case_invalid` | A1, A6 | Недостоверный датчик. Причина — выход за физический диапазон |

## Автоматическая проверка

Из корня проекта с настроенной сборкой выполни `cmake --build build/Release --target check-monitoring`. Тест создаёт временную sc-память, загружает учебные данные и собранное расширение, инициирует действия и проверяет статус, значения и дуги внутри их результатов.

## Как заданы исходные данные

Ситуация наблюдения связывает аппарат, каналы измерения и профиль правил. Канал содержит ссылки на уставки, физические пределы и отсчёты с временем и численным значением. Несколько ситуаций могут описывать один физический датчик. Для классификации используются только дуги из структуры оценок конкретного запуска.

Для прогноза используется скорость между первым и последним отсчётом внутри окна. Длительность нарушения отсчитывается от первого отсчёта непрерывной серии с одной стороны уставки. При наличии предыдущего штатного отсчёта вычисляется также верхняя граница длительности. Если наблюдения не позволяют установить, выдержана ли необходимая выдержка времени, классификация может остаться неопределённой.

Нормы, допустимые исключения по состоянию, правила, критичность и предполагаемые причины находятся в БЗ. Приведённые уставки и параметры относятся к тестовым ситуациям.
